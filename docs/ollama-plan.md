# Ollama — этап 8, версия 0.4

Авторизован пользователем 27.10.2026: локальное извлечение с проверкой и семантический поиск. Используется принятый общий план; повторное согласование архитектуры не требуется.

- Адаптер Ollama только `http://127.0.0.1:11434`, без proxy/redirect/cloud API, выбор только установленных моделей. Проверка capabilities и digest до/после запроса; облачные модели не допускаются. Никаких автоматических pull.
- Экран «Локальные модели»: список моделей, выбор сохранённого снимка и типа, явный запуск извлечения. Результат проходит тот же review, что HTML/PPTX. Также добавить Ollama-шаг в пайплайны.
- Передавать блоки как недоверенные данные отдельно от системных инструкций, требовать структурированный JSON и точные цитаты. Проверять JSON Schema, block IDs, цитаты и literal value; пересказ отмечать `llm_transform`. Инструкции документа не дают модели полномочий вызывать инструменты или менять реестр.
- Бюджет входа: до 12000 символов выбранных блоков, до 200 блоков, без скрытого усечения. Для больших документов можно выбрать блоки в UI; отказ вместо незаметной потери текста. Ответ до 256 KiB, 180 секунд ожидания. Модель, digest, prompt hash, options и run ID сохраняются в provenance; raw-response отдельно на 7 дней с очисткой при запуске и новых вызовах.
- Embeddings bge-m3 по умолчанию, отдельные поколения индекса для model/digest/dimension. Чанки реквизитов по 1500 символов с перекрытием200. Индекс в SQLite, точный cosine + RRF с FTS. Явное построение/обновление кнопкой, статусы покрытия; устаревшие ревизии сразу исключаются при поиске. Атомарная смена поколения только после полного построения; прерванная/ошибочная сборка не меняет действующий индекс.
- Семантический запрос при отсутствии модели/индекса возвращает результаты FTS с предупреждением. Фильтры статуса/типа применяются к обоим каналам до ранжирования. Смена модели/размерности не смешивает векторы. Запросы поиска не изменяют реестр.
