# PPTX и редактор правил/Python — рабочий план

Область подтверждена пользователем: этапы 6 и 7. LLM не входит. Приложение на 8765 остаётся доступным; тестирование идёт на отдельной БД/порту до обновления.

1. PPTX: локальный файл и Confluence-вложение по download/preview ссылке; REST проверяет attachment ID, parent page и версию. Только доверенный HTTPS host и путь download/attachments; redirect запрещён. До 25 MiB файла, 100 MiB ZIP, 2000 entries, 300 слайдов. Ничего не распаковывать на диск. Изображения/SmartArt не интерпретировать, дать предупреждение.
2. Единый NormalizedDocument: текстовые блоки и таблицы, координаты slide_index (с 1), shape_id и cell. Порядок shapes из файла; визуальный порядок не гарантируется. Группы раскрываются рекурсивно. Цитаты и оригинальный PPTX доступны в review.
3. Вложение по умолчанию обновляет существующий объект родительской страницы; если объекта ещё нет, просим сначала импортировать страницу или явно выбрать самостоятельный объект/цель. Привязка вложения не должна перепривязывать страницу.
4. Версии пайплайнов: draft → тест на сохранённых снимках → published (неизменяемый). Правила table, sections, between headings, Python. Конфликт полей по умолчанию исключает поле и даёт предупреждение; overwrite только явный параметр шага. Каждый шаг сохраняет диагностический результат, шаг/версию/доказательства.
5. Python: stdin JSON с документом и кодом → stdout JSON proposals `{field,value,block_ids}` через SDK `emit`. Отдельный одноразовый Docker-контейнер без сети/host mounts/секретов, непривилегированный UID, read-only root, tmpfs, memory512MiB/cpu1/pids64, 30s, ограниченный вывод. Docker найден и доступен; образ собирается из python:3.12-slim. Никакого fallback exec в backend.
6. Выбор опубликованного пайплайна при HTML/PPTX/Confluence импорте и повторная обработка сохранённого снимка. Поля проходят JSON Schema, block IDs проверяются сервером; пользовательский код не может сам назначать provenance. Невалидный шаг блокирует результат, а не скрывает ошибку.
7. Проверки: pytest RED→GREEN, реальный Docker runner (успех, timeout, invalid output, сеть/root FS/ресурсы), production build, browser flow и независимый review. Работающий сервис обновляется только после проверок и проверки отсутствия активного импорта.
