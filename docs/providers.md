# OpenAI-совместимые подключения — версия0.5

В **Модели и API → Подключения OpenAI API** добавьте имя, base URL и API-ключ. Для локального gateway без авторизации снимите «API требует Bearer-ключ».

| Провайдер | Пример base URL | Модель |
|---|---|---|
| OpenRouter | `https://openrouter.ai/api/v1` | ID вида `vendor/model`, выбранный в каталоге OpenRouter |
| LiteLLM локально | `http://127.0.0.1:4000/v1` | alias из конфигурации gateway |
| Другой совместимый сервер | `https://server.example/v1` | ID/deployment alias сервера |

Адрес — корень API, без `/chat/completions`. Для удалённого подключения нужен HTTPS. HTTP разрешён только на loopback. Bearer-ключ хранится в Windows Credential Manager под `ArchitectureRegistryStudio/Providers/<id>`, не в SQLite/экспорте/пайплайне. Пользовательские CA и дополнительные нестандартные auth-заголовки в этой версии не настраиваются; системные HTTP-прокси из env не используются. Перенаправления запрещены.

## Извлечение и поиск

Выберите провайдер и модель **отдельно** для извлечения и embeddings. Каталог `/models` загружается кнопкой; если сервер его не поддерживает, введите имя модели вручную. У внешних каталогов обычно нет надёжного признака embedding capability — выбирайте модель соответствующего назначения.

«Извлечь и проверить» отправляет выбранные блоки и JSON Schema на указанный сервер. Схема полей, точные цитаты, существование блоков, конечность значений и завершение генерации проверяются локально. Получается предложение, а не автоматически сохранённый объект. Перед публикацией проверьте смысл и полноту.

«Построить / обновить индекс» отправляет реквизиты реестра embedding-провайдеру. Поиск «По смыслу и словам» затем отправляет ему текст запроса; сервер активного индекса показан в реестре. Снимки документов и Confluence PAT в эти запросы не включаются. Не указывайте секреты в реквизитах/документах, которые выбираете для модели.

В редакторе пайплайна шаг **LLM** хранит `provider_id` и имя модели. При тесте/публикации/HTML/PPTX/Confluence/replay используется этот профиль. Старые шаги без `provider_id` продолжают использовать локальную Ollama. Сравнение с предыдущей версией пайплайна может вызвать обе настроенные модели.

## Совместимость и версии

- Формат по умолчанию: `response_format: {type: "json_object"}`. Если сервер не поддерживает его, создайте профиль с `text` (контракт JSON в prompt) или `json_schema` (`strict=false`, так как типы полей реестра динамические). Независимо от режима локальная валидация одинакова. Никакого автоматического переключения/retry, способного создать повторные платные запросы.
- По умолчанию `max_tokens=2048`, `temperature=0`, `stream=false`. В расширенных настройках можно выбрать `max_completion_tokens` и отключить передачу temperature. Ollama-specific `think`, `keep_alive`, `num_ctx` во внешний API не уходят.
- Адрес и параметры профиля неизменяемы: для другого endpoint/deployment создайте новое подключение. Ключ можно заменить/удалить; подключение — отключить. Смена ключа меняет credential revision и требует перестроить индекс этого профиля. Отключение не удаляет историю.
- Стандартный API не гарантирует hash весов. `config:…` в provenance — fingerprint конфигурации, **не digest модели**. Сохраняется фактическое имя модели из ответа, если сервер его сообщает. Если upstream заменил веса под прежним alias, создайте профиль с новой меткой deployment и новый индекс. Незаметную замену весов при неизменном имени стандарт API обнаружить не позволяет.
- Поколение индекса сохраняет provider ID, имя/конфигурацию модели, фактическое имя ответа и размерность. Другой провайдер/версия ключа/модель/размерность не смешиваются. Устаревшие ревизии объектов исключаются. Ошибка API оставляет поиск по словам; неудачная пересборка не заменяет прежний индекс.
- Лимиты: выбранный вход со схемой12000 UTF-8 байт/200блоков; сырой ответ256KiB/7дней; HTTP response2MiB (каталог8MiB), чтение до180секунд с connect timeout10секунд. Платные квоты и разрешения задаются у провайдера; billing в приложении не реализован.
