# Script Engine: JavaScript и Node.js Worker

В разделе «Пайплайны» добавьте **Script Engine (JS)**. Укажите код JavaScript и параметры JSON. Доступны async/await, стандартный JavaScript и предустановленный конвертер HTML→Markdown (Turndown с GFM). Произвольные npm-зависимости в шаге не устанавливаются.

## Подготовка

Нужен запущенный Docker Desktop с Linux containers. Node.js на компьютере для исполнения шага не требуется: Node 22 находится в образе.

```powershell
.\scripts\setup-javascript-runner.ps1
```

Git Bash:

```bash
bash scripts/setup-javascript-runner.sh
```

Состояние исполнителя отображается в редакторе и доступно по `/api/javascript-runtime`. При публикации закрепляется ID образа, отдельно от Python-исполнителя. Не удаляйте старые образы, если нужны старые версии пайплайнов.

## Контракт шага

| Имя | Назначение |
|---|---|
| `document.html` | Нормализованный HTML из HTML/Confluence. Скрипты и активные вложения удалены. Confluence Storage XML предварительно обрабатывается существующим парсером макросов. У PPTX этого поля нет |
| `document.blocks` | Исходные блоки с `id`, `text` и координатами источника |
| `document.tables` | Нормализованные таблицы |
| `params` | JSON-параметры, заданные в редакторе |
| `toMarkdown(html)` | Преобразование HTML в строку Markdown |
| `saveMarkdown('page.md', text)` | Добавляет Markdown-файл в результат шага для просмотра и скачивания |
| `emit('owner', value, ['b0'])` | Предлагает значение реквизита с привязкой к исходным блокам |
| `warnings.push('Сообщение')` | Добавляет диагностическое сообщение |

Шаг читает исходный документ и не меняет его для следующих шагов. Результаты JavaScript могут быть переданы последующему LLM как предложения полей, если включено «Передавать результаты предыдущих шагов». Markdown-файлы в LLM-контекст автоматически не добавляются.

## Пример HTML → Markdown → реквизит

Для строки `Владелец: Иван Иванов`:

```javascript
const md = toMarkdown(document.html);
saveMarkdown('page.md', md);

const prefix = params.prefix || 'Владелец:';
const line = md.split(/\r?\n/).find(line => line.includes(prefix));
if (line) {
  const block = document.blocks.find(b => b.text.includes(prefix));
  if (block) {
    const value = block.text.slice(block.text.indexOf(prefix) + prefix.length).trim();
    emit(params.field || 'owner', value, [block.id]);
    warnings.push('Найдено значение: ' + value);
  }
} else {
  warnings.push('Строка с префиксом ' + prefix + ' не найдена');
}
```

Параметры: `{"prefix":"Владелец:","field":"owner"}`. Поле должно существовать в выбранной схеме. Для строк в таблицах адаптируйте поиск к `document.tables`: значение может находиться в соседней ячейке. Для преобразования значений сохраняйте ссылки на те исходные блоки, на которых основано предложение.

## Проверка результата

1. Сохраните новую версию пайплайна.
2. Выберите сохранённый снимок HTML/Confluence и нажмите «Проверить версию».
3. В отчёте раскройте «Шаг N · Script Engine · результаты»: доступны названия выданных полей, сообщения и Markdown с кнопкой «Скачать Markdown».
4. Значения полей смотрите в общей таблице «Было / Стало». После публикации создайте предложение из снимка: там доступны файлы и проверка цитат перед сохранением объекта.

Markdown хранится в результатах теста/предложения, а не записывается скриптом в произвольную папку. Скачивание запускается пользователем. Markdown показывается как текст без исполнения HTML. Файлы успешных шагов не выдаются как полный результат, если следующий шаг завершился ошибкой.

Старые снимки получают HTML из локального сохранённого исходника при запуске; их блоки и доказательства не изменяются. Повторный запрос к Confluence не требуется.

## Ограничения

- Код до 32 000 символов; вход до 16 MiB; общий вывод до 1 MiB.
- До 200 предложений и 5 файлов `.md`, каждый до 256 KiB. В имени файла запрещены пути.
- Worker: 25 секунд, V8 heap 128 MiB. Внешний исполнитель: 30 секунд, контейнер 512 MiB RAM, 1 CPU, 64 PID.
- Без сети, host mounts, Docker socket, секретов и окружения основного приложения; read-only root, непривилегированный пользователь. Worker сам по себе не является песочницей: граница изоляции — Docker. Локального fallback нет.
- Ошибка JavaScript, неверный тип значения или неизвестный ID блока прерывают запуск. Объекты автоматически не сохраняются. `overwrite` регулирует замену предложений так же, как для других шагов.
- `console.log` не попадает в отчёт; используйте `warnings.push`. Ошибки исполнения возвращают общее сообщение без полного stack trace.

Использованы [Node.js Worker Threads](https://nodejs.org/api/worker_threads.html) и [Turndown](https://github.com/mixmark-io/turndown).
