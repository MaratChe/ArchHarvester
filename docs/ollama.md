# Локальная Ollama и поиск

С версии0.5 также доступны [OpenAI-совместимые API](providers.md). Ниже — встроенное подключение Ollama.

## Быстрый сценарий

1. Откройте **Модели и API**, выберите **Локальная Ollama**. Это подключение обращается только к `http://127.0.0.1:11434`. Ollama должна быть запущена на этом компьютере. Автоматического скачивания моделей нет.
2. Для извлечения исходно выбрана **ornith-1.5:9b**, как указал пользователь. Выберите тип и сохранённый снимок HTML/PPTX/Confluence. Снимки появляются после загрузки, независимо от принятия начального предложения.
3. Отметьте нужные блоки и нажмите **Извлечь и проверить**. Вход вместе со схемой ограничен 12000 UTF-8 байт и 200 блоками; большой документ обрабатывайте по разделам. Скрытого усечения входа нет.
4. Проверьте цитаты, заполните пропущенные реквизиты и исправьте неточности. Только подтверждение создаёт/обновляет объект. При обновлении текущие значения остаются в форме до явного применения предложения.
5. Для поиска выберите **bge-m3:latest** и нажмите **Построить / обновить индекс**. В реестре переключите поиск на **По смыслу и словам**.

В списках показываются только локальные модели нужной capability: completion для извлечения и embedding для поиска. Облачные модели отклоняются. Приложение не передаёт PAT, БД или системные файлы модели; в запрос отправляется выбранный текст и схема. Для другого порта/удалённого Ollama в этой версии нет настройки.

## Проверка переноса

Модель получает текст как недоверенные данные отдельно от системных инструкций. Ей не выдаются инструменты и доступ к действиям реестра. Это не обещание иммунитета к prompt injection: значение может быть смыслово неверным даже при правильной цитате, поэтому нужна проверка человеком.

Сервер проверяет JSON Schema поля, известность block ID, точное наличие цитаты в выбранном блоке и завершённость ответа. Неизвестные/повторяющиеся поля и выдуманные цитаты отклоняются. Буквальная строка должна встречаться в цитате с учётом регистра. Если различается только регистр, сервер помечает значение как преобразование и добавляет предупреждение. Числа, boolean и массивы требуют `transformed`, поскольку это преобразование исходного текста.

В review различаются **буквальное извлечение** и **пересказ/преобразование**. В раскрываемом блоке модели доступны имя, digest, prompt hash, длительность и сырой ответ. Provenance принятого значения содержит эти сведения и run ID. Сырой ответ сохраняется отдельно на 7 дней; просроченные записи очищаются при старте, новых вызовах и обращениях к истории. Пока приложение выключено, физической очистки нет. Метаданные принятого результата остаются в истории объекта.

Отклонённые ответы также сохраняются отдельно, если они укладываются в лимит. Ошибка API содержит run ID для диагностики; такой ответ не создаёт предложение и не изменяет реестр. История доступна через `GET /api/llm/runs/{id}/raw`.

Температура0 уменьшает случайность, но не гарантирует точного повторения. Параметры генерации: `num_ctx=16384`, `num_predict=2048`, `think=false`, `keep_alive=2m`. Ответ ограничен256 KiB; транспортный ответ —2 MiB, ожидание чтения —180 секунд. Возможности модели, digest и наличие локальной установки проверяются перед вызовом и после него. Изменение модели во время обработки приводит к отказу.

## Ollama в пайплайне

В **Пайплайны** добавьте шаг **Ollama**, укажите точное имя установленной модели, сохраните новую версию, протестируйте на снимках и опубликуйте. Шаг работает с полным нормализованным документом в пределах того же бюджета. Для выборочного извлечения блоков используйте отдельный экран Ollama.

Действуют общие правила конфликтов: одинаковое поле от нескольких шагов исключается с предупреждением, если явно не включён overwrite. Поля LLM и их цитаты проходят ту же серверную проверку. Версия пайплайна сохраняет имя модели, а каждый запуск — фактический digest; смена тега между разными запусками не маскируется обещанием воспроизводимости. Импорт HTML/PPTX и CQL-job может использовать опубликованный LLM-пайплайн.

## Семантический поиск

Индекс содержит реквизиты объектов, включая пользовательские названия полей из версии схемы. Текст делится на чанки1500 символов с перекрытием200. Сырые исходные документы целиком не индексируются. Найденный объект открывается обычной карточкой с основаниями и цитатами.

Каждое поколение индекса закрепляет имя/digest embedding-модели, размерность и ревизии объектов. Векторы разных моделей и размерностей не смешиваются. Поиск выполняет точный cosine в памяти, а затем объединяет его с ранжированным по BM25 поиском FTS через RRF (`k=60`). Оценка ранга не трактуется как вероятность правильного ответа.

Обновление запускается кнопкой и полностью перестраивает индекс. Старое поколение заменяется атомарно только после успешной обработки и проверки неизменности реестра; ошибка оставляет прежний индекс доступным. Векторы устаревшей ревизии исключаются сразу. После правки/нового объекта обновите индекс; экран показывает покрытие. Если модель/индекс недоступны или digest/размерность изменились, запрос возвращает поиск по словам с явным предупреждением.

Пилотные ограничения:5000 объектов,100 чанков на объект,5 млн компонент векторов суммарно. Число результатов API — до100. Это решение для небольшого локального реестра; массовую фоновую индексацию, автоматическое обновление и векторную СУБД эта версия не добавляет. Индексация выполняется по запросу с индикатором занятости, её неоконченные результаты не публикуются после сбоя/перезапуска.

## Проверки и известные ограничения

Автотесты проверяют недоступность/таймаут Ollama, cloud запрет, JSON/schema, block IDs и цитаты, literal/typed values, границу document/system, digest, хранение/очистку raw, обязательный review, размерность/смену модели, фильтры, устаревшие ревизии, конкурентную правку и fallback FTS.

Реальные локальные прогоны выполнены на синтетических русских документах:

- `ornith-1.5:9b`, digest `e5df7dcdd8a2…`: извлечение четырёх реквизитов в одном smoke —9.33с. Первоначальная капитализация требовала корректной маркировки transformed; это исправлено и проверяется тестом.
- HTML с общей меткой «Решение» показал, что модель может пропустить название. В браузерном review оно заполнено вручную; затем в prompt добавлены kind/level блоков и предпочтение h1. Проверка полноты человеком остаётся необходимой.
- `bge-m3:latest`, digest `790764642607…`:1024 измерения, первый тест embeddings с загрузкой —23.12с. Связанный текст получил cosine0.547 против0.470 у несвязанного. Это smoke, а не статистическая оценка качества.
- Браузерный смысловой запрос «Как не потерять данные при обрыве соединения» поставил решение о доставке выше документа об отпусках, хотя буквальных совпадений запроса не было. Проверены desktop/mobile, ручное сохранение и отсутствие перезаписи текущих полей при повторном извлечении.

Пиковая RAM/VRAM не измерялась. Качество на корпоративном корпусе, больших презентациях и пользовательских схемах требует отдельной оценки; проверки не использовали реальные документы Confluence.

Используемые контракты Ollama: [официальная API-документация](https://github.com/ollama/ollama/blob/main/docs/api.md), [структуры chat/embed](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml).
