# PPTX и пайплайны (0.3)

## Презентации

В **Загрузка файлов** выберите `.pptx` (до 25 MiB). Для таблиц используйте левый столбец с названием реквизита и правый со значением. Номер таблицы считается с 0 по всей презентации.

В **PPTX из Confluence** выберите ранее настроенное подключение, вставьте ссылку `https://wiki.example/confluence/download/attachments/123/file.pptx` либо ссылку просмотра с `?preview=/123/456/file.pptx`. Нажмите **Проверить вложение**, проверьте название/версию и запустите загрузку. Токен читается из Windows Credential Manager; в Python-шаги он не передаётся.

По умолчанию вложение дополняет объект, ранее созданный из родительской страницы. Если такого объекта этой версии схемы ещё нет, сначала подтвердите предложение страницы. Можно явно выбрать существующий объект либо включить **Создать отдельный объект**. Уже связанное вложение нельзя переназначить другому объекту этим действием.

Результат открывается в обычной форме проверки. Для обновлений текущие поля остаются в форме до нажатия **Применить предложение**. У цитат видны номер слайда (с 1), ID фигуры и координаты ячейки в JSON. Исходный PPTX можно скачать. Повторная загрузка той же версии и конфигурации не создаёт дубликат предложения.

Извлекаются текстовые блоки, таблицы и вложенные группы. OCR, изображения, SmartArt, заметки докладчика и визуальный рендер слайдов не поддерживаются. Текстовый порядок соответствует структуре файла, а не расположению фигур на экране. Строки с объединёнными ячейками пропускаются с предупреждением. Ограничения: 300 слайдов, 2000 ZIP entries, 100 MiB распакованного содержимого, 20000 блоков / 2 млн символов, глубина групп 20. DTD запрещены во всех кодировках XML; ZIP не распаковывается на диск.

Вложения загружаются одним запросом с индикатором занятости; отдельная устойчивая очередь/retry для них пока не реализована. Сбой можно повторить из той же формы. Фоновая очередь страниц Confluence продолжает работать как раньше. HTTP redirect и внешние download URL не допускаются; версия файла закрепляется параметром запроса. Серверные метаданные берутся через REST, а не из имени ссылки.

## Редактор правил

1. Откройте **Пайплайны**, укажите ключ (латиница), название и версию типа объекта.
2. Добавьте шаги и задайте порядок: таблица, разделы, текст между двумя границами, Python.
3. Сохраните новую версию. Сохранённые версии неизменяемы; правка создаёт следующую версию того же ключа.
4. Выберите до 10 сохранённых снимков и нажмите **Проверить версию**. Снимки появляются после загрузки HTML/PPTX/страницы, даже если предложение ещё не принято.
5. Просмотрите значения, предупреждения и разницу с предыдущей опубликованной версией. Ошибка предыдущей версии показывается отдельно и не блокирует проверку исправления.
6. Нажмите **Опубликовать версию**. Теперь её можно выбрать при загрузке HTML/PPTX или запуске CQL-импорта. Кнопка **Создать предложение из этого снимка** позволяет повторно обработать сохранённый документ без скачивания источника.

Правило **Между границами** ищет точное совпадение текста отдельного блока без учёта регистра. Например, поле `problem`, начало `Проблематика`, конец `Задачи проекта`. Обе границы должны встретиться ровно один раз и в правильном порядке; сами границы исключаются. Неоднозначность даёт предупреждение, без догадок.

Шаги последовательно читают один нормализованный документ. Они не изменяют его и не получают результаты предыдущих шагов. Повторное предложение одного поля исключает это поле с предупреждением. Только явный **overwrite** позволяет шагу заменить предыдущее предложение. Входные правила можно переносить как JSON через раскрываемый редактор; YAML не добавлен.

JSON Schema проверяет типы/ограничения значений, сервер проверяет наличие блоков-доказательств. Незаполненные обязательные поля можно добавить вручную перед публикацией объекта. Наличие корректного block ID не доказывает смысловую верность значения: окончательную проверку выполняет пользователь. В provenance сохраняются версия, ID, hash пайплайна, номер шага, снимок и цитаты.

## Python

Для выполнения нужен Docker Desktop с Linux containers. Подготовка локального образа:

```powershell
.\scripts\setup-python-runner.ps1
```

В текущей установке образ уже собран и проверен. При отсутствии Docker/образа Python-шаг завершается явной ошибкой; обычные правила продолжают работать. Образ опубликованной версии закреплён по image ID: сохраните старые образы, если нужна воспроизводимость. Если закреплённый образ удалён, создайте и протестируйте новую версию.

Доступны стандартная библиотека Python 3.12 и SDK:

```python
# document: contract_version, snapshot_id, blocks, tables, warnings
# block: id, text, kind и html_path либо slide_index/shape_id/cell
# params: JSON-объект из редактора
for block in document['blocks']:
    prefix = params.get('prefix', 'Владелец:')
    if block['text'].startswith(prefix):
        emit('owner', block['text'][len(prefix):].strip(), [block['id']])
warnings.append('Проверьте владельца по исходному документу')
```

`emit(field, value, block_ids)` добавляет предложение. `print` нарушает выходной JSON-контракт: для диагностики используйте `warnings`. Ошибка кода блокирует результат этого запуска; частичное предложение не сохраняется.

Каждый шаг запускается в одноразовом контейнере: пользователь 65534, без сети, без host mounts и Docker socket, read-only root, сброшенные capabilities, no-new-privileges, стандартный seccomp Docker, tmpfs 16 MiB, 512 MiB RAM, 1 CPU, 64 PID, максимум 30 секунд и 1 MiB каждого потока вывода. В контейнер попадают только код, нормализованный документ и params; БД, PAT и окружение основного сервиса не передаются. Запуск контейнера и его очистка также могут занять несколько секунд.

Контейнер — граница исполнения; это не проверка безопасности самого кода. Установка дополнительных библиотек/доступ к сети из шага не предусмотрены. Контейнеры и результаты тестов не запускаются сами при открытии страницы; выполнение происходит по действию пользователя или выбранному им импорту.

## API и проверка

Новые маршруты: `/api/pptx/{uploads,resolve,attachments}`, `/api/pipelines`, `/api/pipelines/{id}/{tests,publish,propose}`, `/api/python-runtime`, `/api/snapshots`. Изменяющие запросы требуют локальный `X-Local-Token`, как прежде. HTML/PPTX upload принимает `pipeline_id`; CQL job закрепляет выбранный `pipeline_id`, в том числе при retry.

```powershell
$env:RUN_DOCKER_TESTS='1'
.venv/Scripts/python.exe -m pytest -q --basetemp=output/verification-pptx
npm.cmd --prefix frontend run build
```

API Confluence сверялся с [примером загрузки вложений Atlassian](https://developer.atlassian.com/server/confluence/rest/v901/intro/) и [REST attachments](https://developer.atlassian.com/server/confluence/rest/v1002/api-group-attachments/); группы фигур — с [python-pptx](https://python-pptx.readthedocs.io/en/latest/api/shapes.html). Совместимость с корпоративным Confluence 7.13.7 требует проверки на реальном сервере; автоматические и браузерные проверки использовали имитатор.
