# Типы объектов и конструктор (0.6)

1. Откройте «Типы объектов» → «Создать новый тип».
2. Укажите название, уникальный ключ (например information_system) и описание назначения типа.
3. Добавьте реквизиты. Для каждого задайте название, ключ, вид данных и обязательность при публикации. В раскрывающемся разделе можно добавить описание для пользователя/LLM и варианты выбора (по одному на строке).
4. Нажмите «Создать тип». Он появится в списках ручного создания объектов, импорта и редактора пайплайнов.

До40реквизитов: текст, число, целое, да/нет, дата, список строк и выбор из строковых вариантов. Ключи — строчные латинские буквы/цифры/подчёркивание, начиная с буквы, до64символов. Ключи реквизитов не повторяются. Обязательность проверяется при публикации; черновик может быть неполным.

Обязательный строковый title используется как название объекта. В конструкторе его нельзя удалить или переименовать ключ; пользовательское название/описание поля можно менять. Расширенный JSON также проверяется перед сохранением. При создании самостоятельного типа API проверяет уникальность ключа и наличие обязательного строкового title; прежний POST без create_new сохраняет совместимость.

Для изменения типа используйте «Создать следующую версию». Ключ типа закреплён, старая схема и объекты не меняются. Обычное редактирование описаний сохраняет существующие minLength/maxLength/числовые границы и metadata. Смена вида поля явно сбрасывает его специальные ограничения.

«Редактировать JSON Schema» открывает расширенный режим. Возврат в конструктор читает отредактированный JSON. Вложенные объекты/$ref и прочие неподдерживаемые конструкции по-прежнему отклоняются сервером. Числовые/boolean enum из ранее созданных схем сохраняются при обычной правке; редактировать их варианты следует через JSON. Список строк в карточке объекта вводится через точку с запятой.
