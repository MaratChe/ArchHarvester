# Решения АК из PPTX-вложений по CQL

1. Откройте **Confluence**, выберите подключение и задайте CQL страниц заседаний, например `type = page AND space = "ARCH" AND label = "committee"`.
2. Нажмите **Найти страницы** и отметьте нужные страницы.
3. В **Что загружать** выберите **PPTX-вложения страниц — отдельный объект на презентацию**.
4. Выберите тип/версию схемы для решения АК и способ извлечения либо опубликованный пайплайн, работающий с PPTX.
5. Нажмите **Загрузить выбранные**. Очередь сначала проверяет вложения страниц, затем скачивает и обрабатывает каждую презентацию отдельно.
6. В результатах откройте **Проверить предложение** напротив каждой презентации. После подтверждения появится отдельный объект решения.

Одна страница с тремя PPTX даёт три независимых основания и три предложения. Содержимое HTML страницы в этом режиме не импортируется. Объект родительской страницы не выбирается как цель автоматически. Страница без презентаций отмечается как проверенная с количеством PPTX=0.

## Повторная загрузка

Повторите поиск CQL и загрузку. Идентичность источника определяется подключением и стабильным attachment ID, не названием файла. При обработке запрашивается актуальная версия вложения; скачивание закреплено за этой версией. Переименование и новая версия того же вложения сохраняют связь с объектом.

- Неизменённое вложение при том же пайплайне/способе извлечения повторно использует предложение.
- Новая версия создаёт предложение обновления связанного объекта. Сохранённые значения не заменяются до ручной проверки.
- Пока первоначальное предложение не принято, новая версия заменяет ожидающее предложение; объект автоматически не создаётся.
- Если файл удалён и загружен заново с новым attachment ID, это новый источник, даже при прежнем имени. Автоматического сопоставления по названию нет.
- Для уже связанных источников используется существующая привязка, в том числе созданная ранее ручным импортом PPTX. Автоматического переназначения нет. Изменение версии схемы объекта требует отдельной миграции, как в других режимах импорта.

## Очередь и ограничения

Задание сохраняется в SQLite, восстанавливается после перезапуска и поддерживает отмену. В строке каждого вложения показаны имя, ID, родительская страница, версия, состояние и ошибка. Ошибка одного PPTX не останавливает остальные. **Повторить ошибки** создаёт задание только для неуспешных элементов; если не удалось получить список вложений, повторяется проверка этой страницы.

Импортируются собственные вложения страницы с расширением `.pptx`, а не произвольные ссылки на презентации других страниц или внешних сайтов. `.ppt` и `.pdf` не импортируются. Список вложений читается с пагинацией. Ограничения: 500 выбранных страниц, 2500 суммарных этапов «страница/вложение» в задании, до 5000 элементов списка вложений на странице, 25 MiB на PPTX. При превышении лимита выводится ошибка: сузьте CQL. Существующие ограничения парсера PPTX остаются в силе.

Токен и системные/корпоративные сертификаты используются из настройки подключения. Реальные корпоративные страницы требуется проверить в вашей среде; автоматические тесты используют имитатор Confluence.


## Последовательная проверка результатов

Откройте предложение из результатов нужной загрузки. В форме доступны «Следующее предложение» (без сохранения) и «Опубликовать и перейти к следующему». Переход выбирает ожидающее проверки предложение только этой загрузки, пропускает уже обработанные и после конца списка возвращается к ранее пропущенным. При отсутствии ожидающих предложений показывается сообщение. Для изменённых полей переход без сохранения требует подтверждения. Обычная публикация в этом режиме оставляет форму открытой; «К списку» возвращает к результатам выбранной загрузки. Это работает и для HTML-страниц, и для PPTX-вложений.
