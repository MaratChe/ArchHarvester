# Новый тип и минимальный конструктор

Запрос пользователя: создание самостоятельного типа через UI и простой конструктор его описания. Используем существующий профиль JSON Schema, без новой миграции.

- Страница типов: отдельное действие «Создать новый тип», существующие версии остаются неизменяемыми.
- Редактор: название, уникальный ключ типа, описание; до40реквизитов с названием, ключом, видом, обязательностью и описанием. Виды: текст, число, целое, да/нет, дата, список строк, выбор из строковых вариантов. Начальный реквизит title обязателен и используется как название объекта.
- Добавление/удаление реквизитов, проверка пустых и повторных ключей. JSON Schema остаётся доступной как расширенный режим. Не терять ограничения/metadata существующих схем при обычной правке названия/описания; изменение вида поля явно сбрасывает его ограничения.
- Новый ключ проверяется UI и сервером (create_new), чтобы «создать тип» не превратилось в новую версию при конфликте. Старый POST /types без create_new сохраняет совместимость.
- Проверить создание нового типа, повтор ключа, новую версию, сохранность старых объектов, JSON roundtrip, динамическую форму объекта; browser QA на отдельном реестре, backup и обновление8765.
